# Decision: Disposition of IndexedDB-only memory and adjacent domains

- **Status:** accepted 2026-11-26 — architecture/retention decision only; this ADR authorizes **no code deletion and no daemon port**.
- **Scope:** the IndexedDB-only memory pillars and adjacent stores named in the audit: Echo Chips, Director sessions/notes, Event Log/ledger, Lifetime Artifacts, Provisioning Sessions, Peers roster, voice-profile blobs, plus the sync-lease/tombstone bookkeeping that sits beside them.
- **Out of scope:** Short-Term Memory and the Text Journal (LTMM) — already daemon-ported to `summaries`, `journal_entries`, `memory_embeddings` (`crates/anima-core/src/memory/mod.rs`, [`feature-parity-checklist.md`](./feature-parity-checklist.md)). Chat sessions and cards have separate owners. This decision does not reopen the TS remote-sync retirement gate in [`plan-ts-remote-sync-retirement.md`](./plan-ts-remote-sync-retirement.md).
- **Cross-links:** [`data-catalog.md`](./data-catalog.md) (key inventory; short disposition pointers at the relevant headers) · [`design-flutter-godot-pivot.md`](./design-flutter-godot-pivot.md) (Flutter is the sole maintained renderer; Vue is the behaviour reference) · [`decision-client-local-tts-pcm.md`](./decision-client-local-tts-pcm.md) / [`decision-bridge-scope.md`](./decision-bridge-scope.md) (client-local audio) · [`decision-audit-archive-retention.md`](./decision-audit-archive-retention.md) (different, daemon-side audit log).

## Context (source-verified 2026-11-26)

- The Rust memory core owns exactly two lanes: daily `summaries` + append-only `journal_entries` (P7 memory/journal) and `memory_embeddings` + retrieval (P7 retrieval). Its module doc explicitly says **"Not in scope (P9): lifetime artifacts, echo chips, event-log/ledger, and LLM-powered 5W analysis"** (`crates/anima-core/src/memory/mod.rs:28`). No table, RPC verb or service exists for any in-scope domain.
- The daemon vault `memory` domain serializes only `summaries`, `journal_entries`, `memory_embeddings` (`crates/anima-core/src/vault.rs:9,316,578-648`). It is **not** an export path for chips, lifetime artifacts, director notes, event-ledger entries or peers.
- Flutter's memory screen calls `stmmList`, `stmmRebuild`, `journalSearch`, `journalAppend` and `retrievalStatus` only (`apps/flutter/lib/features/memory/memory_screen.dart:54-136`; `apps/flutter/lib/daemon_client/daemon_client.dart:918-997`). It has no screen, RPC call or prompt-injection path for any in-scope domain. The "lifetime archives, and echo chips" phrase in `apps/flutter/lib/features/settings/settings_catalog.dart:178` is a stale description, not an implemented feature, and there is no corresponding parity row to change.
- Neither echo chips nor lifetime artifacts are irreplaceable user-authored records: chips are synthesized by `synthesizeForCharacter()` over a TS chat-evidence window (`stores/echo-chips.ts:219,273`), and the lifetime artifact is distilled by `buildBaseArchivePrompt()` from source docs that already prefer daemon `summaries`/`journal_entries` when `hasDaemonMemory()` is true (`stores/memory-lifetime.ts:326,758,841,861,1198`). The **existing** distilled artifact/chips are still lost without export, and regeneration needs a working TS pipeline (and, for chips, TS chat sessions that are not daemon-exported).
- Every in-scope domain still has live TypeScript consumers (Vue web / Electrobun reference): chips in `stores/chat/session-store.ts:1443,1547`, `stores/companion.ts:254`, `stores/agentic.ts:447` and `JournalPreviewModal.vue:75`; the event ledger in `stores/proactivity.ts:699` and the Event Ledger pane; director notes in `stores/modules/artistry-autonomous.ts` via `director-notes.repo.ts`; lifetime/provisioning in `stores/memory-lifetime.ts`; peers in `stores/peers.ts` and `composables/use-peer-embassy.ts`; voice-profile blobs in `stores/providers.ts` and `composables/use-local-voice-clone.ts`.
- `settings/speech/voice-profiles` is already a daemon-backed `settings/speech` field (opaque JSON); only the reference-audio blobs in localforage remain client-side ([`data-catalog.md`](./data-catalog.md) §4.4, §3.1.2–3.1.3).
- There is no daemon trust model for external peers yet: remote-client trust is explicitly out of scope of [`decision-byos-identity.md`](./decision-byos-identity.md), and the daemon has one shared `authToken`, no per-peer identity or revocation.

## Decision

Rules: **PORT** only where a daemon service and a real maintained-client consumer both exist; **ARCHIVE** (keep as TypeScript-reference-only, no daemon port) where the Vue reference is still live but Flutter has no consumer; **DROP** only where no reference consumer survives. Conservative default is ARCHIVE — a port without a consumer would create a second state writer for nobody.

## Consequences

- No new daemon tables, RPC verbs or migration work are promised by this ADR. Daemon state stays authoritative for the lanes it already owns; no second writer is created for a client with no consumer.
- The Vue web / Electrobun reference keeps its stores and behaviour until the separately gated TS business-logic retirement. ARCHIVE is therefore a survival classification, **not** a deletion order: no code or data is removed here.
- The loss/export notes are the retention contract. "Lost at TS retirement" means the key lives only in browser IndexedDB/localStorage/localforage and is **not** exporter-covered: `vault.archive` covers only daemon `summaries`/`journal_entries`/`memory_embeddings` and the separate audit archive covers only daemon logs, so IndexedDB artifacts needing survival require their own export before TS retirement. Where a row promises no export, that is a deliberate acceptance of loss, not an oversight.
- Reversibility: any future port is a new ADR that must name the Flutter consumer and the daemon storage/RPC owner. A stale settings description in Flutter is not a consumer.
- The stale catalog shapes and key names listed above are documentation drift to be fixed in a separate minimal edit; this ADR does not rewrite the catalog entries.
