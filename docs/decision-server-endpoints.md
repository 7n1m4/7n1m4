# Decision: Fate of remaining `apps/server` TypeScript endpoints

- **Status:** accepted (2026-11-22)
- **Bead:** `airi-1h6`
- **Scope:** the five groups still mounted by `apps/server/src/app.ts` — auth/OAuth, characters, providers, chats/sync, gdrive/manifest. This is a retirement/ownership decision, **not** a deletion of the TS layer. Where this decision refers to retiring the "Vue/desktop reference", it means the opt-in TS remote-sync mirror and the Electrobun desktop shell/business logic; the Vue **web** UI renderer (`apps/stage-web`) remains a maintained full-parity renderer and is never retired by this decision or its follow-ups.

## Context

The target architecture is "one core, many surfaces": a long-lived Rust daemon owns state and Flutter/Godot/Vue surfaces are thin clients ([`README.md`](./README.md), [`design-flutter-godot-pivot.md`](./design-flutter-godot-pivot.md)). In daemon mode there is one writer for the application store; clients must not open competing local writers ([`design-daemon-core-rpc.md`](./design-daemon-core-rpc.md)). The fork is local-first, zero-account, and BYOS: multi-device state belongs in the user's own storage, not in an AIRI-hosted custody database ([`project-byos-cloud-sync.md`](./project-byos-cloud-sync.md)). The realistic deployment is one owner/local user and their own devices; hosted multi-user community features are not an architecture requirement.

The existing `apps/server` is a Hono/Postgres/better-auth Node service (`apps/server/package.json`, `apps/server/docker-compose.yml`). It remains in-tree and compilable. **There is no Rust REST equivalent.** The Rust side is a local authenticated WebSocket RPC gateway (`crates/anima-channel/src/lib.rs`, `crates/anima-channel/src/server.rs`) with daemon-registered `renderer.*` handlers (`crates/anima-daemon/src/gateway.rs`). Searches found no `axum`/`warp`/`actix-web` dependency or `Router::new`/`.route()`/HTTP handler registration in `crates/`, and no `/api/*` REST server. RPC handlers such as `core.status`, `providers.list`, and `chat.history` are WebSocket actions, not REST endpoints. Do not describe them as a REST replacement.

## Source-verified callers

- **Vue/desktop TS (`packages/stage-ui`, `apps/stage-web`, `apps/stage-tamagotchi`):**
  - Auth: `packages/stage-ui/src/libs/auth.ts` uses `better-auth/vue` against `SERVER_URL = import.meta.env.VITE_SERVER_URL || 'http://localhost:3000'`. `fetchSession()` returns early unless `localStorage['settings/privacy/remote-sync-enabled'] === 'true'`; `packages/stage-ui/src/stores/auth.ts:24-37` also only fetches/clears the session when `settings.remoteSyncEnabled` changes. Sign-in UI exists in `packages/stage-ui/src/components/auth/LoginDrawer.vue` and `apps/stage-web/src/pages/auth/login.vue`. `isAuthenticated` is `!!user && !!session` and is false by default.
  - Characters: `packages/stage-ui/src/stores/characters.ts` calls all seven Hono client routes via `useLocalFirstRequest`. The helper (`packages/stage-ui/src/composables/use-local-first.ts`) runs `local()` first and only attempts `remote()` when `allowRemote()` is true or, by default, `useAuthStore().isAuthenticated` is true. With remote sync off (stored default `false` in `packages/stage-ui/src/stores/settings/general.ts:33`) and no session, the local branch is the production path. Like/bookmark buttons exist in `packages/stage-pages/src/pages/v2/index.vue:173,192`.
  - Providers: `packages/stage-ui/src/stores/provider-catalog.ts` calls `GET /api/providers`, `POST /api/providers`, `PATCH /api/providers/:id`, `DELETE /api/providers/:id` under the same local-first helper. `GET /api/providers/:id` has **no** production caller.
  - Chats: `packages/stage-ui/src/stores/chat/session-store.ts:139-212` calls `POST /api/chats/sync` via `syncSessionToRemote()`, but `allowRemote: () => remoteSyncEnabled.value && isAuthenticated.value` and `scheduleSync()` returns immediately when `remoteSyncEnabled` is false. Both are false by default.
  - gdrive: no production caller. Searches over `packages`, `apps`, `apps/flutter/lib`, and `godot` found only `apps/server` route/service/DI/test references to `gdrive`, `/api/gdrive`, and `cloud-providers-manifest.json`. The documented Google Drive AppData bootstrap is explicitly client-side and zero-custody (`docs/project-byos-cloud-sync.md:222-234`); the `/api/gdrive` routes are an orphaned server-side variant.
- **Flutter:** no HTTP calls to these endpoints. `apps/flutter/lib/connection/connection_settings.dart` and `apps/flutter/lib/daemon_client/daemon_client.dart` parse WebSocket URLs; `direct_websocket_transport.dart` connects to the daemon on `ws://127.0.0.1:6121/ws`.
- **Server deployment:** `apps/server/docker-compose.yml` publishes the service on host port 6112 for a local/dev deployment. No default client points at it. `VITE_SERVER_URL` is read only by `packages/stage-ui/src/libs/auth.ts` (`SERVER_URL` fallback `http://localhost:3000`); the default-off remote-sync gate is what keeps that client from issuing requests in normal desktop use.

## Decision

The decision rules are: daemon-owned state must not gain a second authoritative REST writer; opt-in TS remote sync may remain only while the Electrobun desktop shell/TS business logic is still being kept alive and only as a non-authoritative mirror (the Vue web renderer stays either way); surfaces with no caller, and features whose real design is local/daemon-owned or BYOS, are retired or replaced rather than preserved "just in case."

| auth/OAuth (`/api/auth/*`)                                                                      | **Stay as opt-in remote sync — temporary.** | It is the gate for the still-live opt-in TS mirror/Electrobun desktop shell's optional account/session path (`remoteSyncEnabled` default false); this does not retire the Vue web renderer. ### What replaces the cloud-community features

- **Likes/bookmarks:** local card/character metadata written through the daemon's card state (or an explicit card extension field), surfaced in the Vue web renderer reference and Flutter/Godot over daemon RPC. Counts from a hosted registry are not a goal; there is no community backend to keep them honest.
- **Multi-device chat mirror:** daemon-owned chat snapshots exported to and imported from the user's BYOS target (S3/R2/local FS) with an explicit conflict policy, or a paired daemon-to-daemon sync over the existing authenticated gateway. No AIRI-hosted REST database, no account requirement, no second writer. This is a follow-up design, not shipped code.
- **Opt-in remote sync for auth/characters/providers:** remains only while the opt-in TS mirror and the `apps/stage-tamagotchi` Electrobun shell/business logic are live. Retirement removes that mirror/shell logic, not the Vue web UI renderer; it requires all business logic in Rust/daemon plus Flutter frontend parity and explicit approval (Wave 5 decision C in `design-flutter-godot-pivot.md`); follow-up `airi-3mp`, with `airi-3cp` remaining **DO NOT START** until the gate passes.

### What is NOT implemented / NOT claimed

- No Rust REST equivalent of any listed endpoint exists. The daemon's WebSocket RPC handlers are not HTTP routes.
- The TS layer is **not gone**. `apps/server` still mounts all five groups; stage-ui still contains the Hono client and local-first remote branches; Flutter/Godot simply never call them.
- Likes/bookmarks replacement (`airi-1gu`), BYOS/gateway chat sync replacement (`airi-94l`), endpoint retirement (`airi-x41`), and the remote-sync retirement gate (`airi-3mp`) are filed follow-ups, not completed work.
- This decision does not authorize deleting endpoints or callers. Route removal happens only in the scoped follow-ups after their caller checks.
